# presentedAerofoilCase

The complete OpenFOAM case for compressible flow over a symmetric aerofoil with physics-driven adaptive mesh refinement, as reported in the article.

**Solver:** `overRhoPimpleDyMFoam` (compressible, density-based PIMPLE with dynamic mesh)

---

## Prerequisites

1. OpenFOAM v2312 sourced in the current shell:
   ```sh
   . /usr/lib/openfoam/openfoam2312/etc/bashrc
   ```

2. Both C++ components compiled (see [`OpenFOAMCode/README.md`](../../OpenFOAMCode/README.md)):
   - `hexahedralMeshGenerator`
   - `libstructuredPythonMotionSolver.so`

3. An initial mesh already generated by `meshGeneration/GenerateMesh.py` with `CASE_PATH` pointing to this directory. The output should include:
   - `symmetricAirfoil` (hex geometry file)
   - `constant/structuredMesh.Orig/`

---

## One-Time Mesh Setup

Run these once after generating the mesh files:

```sh
hexahedralMeshGenerator symmetricAirfoil   # builds constant/polyMesh
topoSet                                    # applies boundary point sets
createPatch -overwrite                     # creates named boundary patches
```

---

## Running the Simulation

```sh
cp -r 0.steadyState/ 0    # restore initial fields
./runMeshMovement          # reset caches and launch the full simulation
```

`runMeshMovement` performs the following steps automatically:
1. Sources the OpenFOAM environment.
2. Removes stale `structuredMesh`, cache files, time directories, and post-processing output.
3. Copies `constant/structuredMesh.Orig/` to `constant/structuredMesh/`.
4. Runs `cycleRefinement.sh 2000` (60 adaptive cycles, each 1 timestep long).
5. Disables refinement and runs `overRhoPimpleDyMFoam` for the remaining timesteps up to t = 2000.

---

## Refinement Cycle (`cycleRefinement.sh`)

The script alternates between two modes in a 30-step period:

| Steps in period | Mode | `NEUMANN_ITERATIONS` in `RefineMesh.py` |
|-----------------|------|-----------------------------------------|
| 1 – 29 | Normal (Dirichlet) | 0 |
| 30 | Neumann | user-supplied argument (default: 2000) |

This allows boundary nodes to relax periodically while keeping them fixed for most steps. Run it manually with a custom Neumann count:

```sh
./cycleRefinement.sh <neumann_iterations>
```

---

## Toggling Refinement

Refinement is controlled by `system/rRefinementDict`:

```
customRefinement
{
    refinement      true;    // set to false to freeze the mesh
    fieldName       "p";
    timeCoefficient 1;
}
```

Use `foamDictionary` to change it at any point:

```sh
foamDictionary -entry customRefinement/refinement -set false system/rRefinementDict
```

## Case Structure

```
presentedAerofoilCase/
├── 0.steadyState/          # initial field snapshot (U, p, …)
├── constant/
│   ├── polyMesh/           # OpenFOAM mesh (created by hexahedralMeshGenerator)
│   ├── structuredMesh/     # live structured metadata (updated each timestep)
│   └── structuredMesh.Orig/# original structured metadata (read-only backup)
├── system/
│   ├── controlDict         # time control
│   ├── rRefinementDict     # refinement toggle and parameters
│   ├── fvSchemes / fvSolution
│   ├── topoSetDict + boundary point files
│   └── createPatchDict
├── Geometry/               # geometry scripts (shared with meshGeneration)
├── TTM/                    # TTM solver (shared with meshMovement)
├── meshGenerationFiles/    # mesh-file writers (shared with meshMovement)
├── RefineMesh.py           # mesh adaptation entry point (called by motion solver)
├── cycleRefinement.sh      # alternating Dirichlet/Neumann run script
└── runMeshMovement         # full reset + run script
```
